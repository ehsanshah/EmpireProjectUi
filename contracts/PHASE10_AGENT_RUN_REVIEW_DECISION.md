# Phase 10 Agent, Run and Review contract decision

The supplied Engine contract section 10 proposes `GET P/agents`, `POST P/memberships/{id}/checks`, `POST P/work-items/{id}/assignments`, `GET P/runs`, Run lifecycle commands, `GET P/reviews` and review decisions. Section 11.3 describes plan approval and section 12 describes scoped events. These are route proposals, not verified wire schemas. No OpenAPI, staging host, test identity, credential grant, probe result example, operation envelope, Run SSE event, artifact metadata, review policy or receipt example is available.

Phase 10 therefore uses a **local deterministic Demo adapter** mounted on the shared Demo client. It does not send requests to an Agent, MCP server, API connector, storage or Engine. The existing Live client remains separate and cannot fall back to Demo Agent responses. A configured Demo connector starts disconnected, unauthorized, unchecked and unready. A visible simulated check can make it ready only inside the local fixture. All generated Run events, receipts, artifacts and test evidence are explicitly simulated.

The Demo command boundary requires the current Phase 09 plan approval, approved Agent-role task, separate execution request, valid project membership, required capability, current issue version and idempotency key. Run start returns a queued local operation; only its completion receipt marks the Run running. Pause, cancel and resume target a Run ID and ETag. Cancellation request and acknowledgement are distinct. Continued actions revalidate plan approval and membership readiness. Review decisions require current review/artifact version, a nonempty reason and a current grant from the Demo review policy; the producing Agent is barred. Rejection retains artifact v1 and requires a new attempt/submission v2. Acceptance changes only the Run/review projection. It does not change issue business status, Done or shipping.

The Demo reviewer fixture grants `review.decide` to `sara-farahani`; this is an explicit local policy record, not a blanket Scrum Master or administrator rule. No new agent or person identity is inferred. Costs remain unknown with an explicit unknown unit. The simulated artifact version diff is a comparison of Demo descriptors, not a real work-product diff. Phase 11 artifact access/delivery is outside this phase.

To reconcile Live: Backend and Agent platform must supply actual schemas for membership/grant/capability/probe, assignment and TaskEnvelope, Run attempts/checkpoints/control commands, operation polling and scoped event replay, Review policy/verdict/history, and receipts. IAM must provide authorized producer and independent reviewer test identities. DevOps must provide reachable staging and BFF session/CSRF inputs. Storage must provide versioned artifact metadata/access tickets and test-evidence provenance. Until then Live remains blocked.
