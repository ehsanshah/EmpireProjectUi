# Phase 06 Sprint planning boundary — proposed, not Engine verified

Source: `reference/EmpireProject_UI_Engine_API_Contract_FA_v1.0.md` sections 4–5, operation catalog and shared UX states; `phases/06_BACKLOG_SPRINT_AND_CAPACITY_PLANNING.md`.

The supplied reference proposes Sprint read/update, lifecycle previews/actions and sprint-fit simulations. It does not provide actual OpenAPI, operation IDs, wire envelopes, role grants, policy validators, graph/capacity snapshot formats, staging access or test identities. The shared `CoreClient` therefore has typed planning methods with a local Demo implementation; the Live implementation fails explicitly for Sprint planning, rank, fit and lifecycle writes. No invented route is sent.

Demo seeds the existing Sprint 12 as active with its baseline **unrecorded**, and Sprint 13 as planned. The current 14-issue fixture is unchanged. Capacity and estimates are unknown unless a human enters them. A start captures an immutable commitment baseline from assigned issues and leaf estimates; a later scope change is logged separately. Parent estimates are excluded whenever an included parent has a child in the project hierarchy, even if that child is in another Sprint. Points, hours and available capacity remain separate. A fit result is `fit_unknown` if any leaf estimate or either capacity unit is missing; otherwise it is `fits` or `does_not_fit` against stated Demo capacity. Graph and capacity snapshot references are explicitly Demo references.

Lifecycle previews capture Sprint and relevant issue versions and expiry. Commands recheck version, permission, CSRF and idempotency. Completion requires a destination for every unfinished issue and a reason for each deferred item; a changed unfinished set rejects the action. Receipts are Demo only. The Sprint Goal remains `unassessed` regardless of completed points. DoD text is editable and visible; the supplied Engine contract has no evidence schema to verify DoD per item, so the Demo does not assert that criteria passed. Reopen changes lifecycle state without silently restoring disposed scope. The Demo session grants planning controls to its named review user; the UI reflects returned capabilities, while the Demo adapter enforces them again at write time.

Backend/Product must reconcile hierarchy and cross-Sprint parent policy, rank anchors/revisions, Sprint roles, Goal/DoD validation and evidence, capacity unit semantics, baseline/scope policy, unfinished-work dispositions, async operation/receipt shape and report metric definitions. IAM must supply scoped identities/BFF session/CSRF. DevOps must supply reachable non-production staging. Exit evidence is actual schema/operation IDs, permission tests and authenticated staging cases for 403, 409, 412, 422, idempotency replay, fit unknown/over-capacity, baseline preservation and completion disposition.
