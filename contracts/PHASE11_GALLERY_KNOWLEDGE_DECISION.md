# Phase 11 Gallery and Knowledge contract decision

The supplied Engine contract sections 7.3, 10, 12 and 13 propose Gallery, artifact metadata/access tickets, Knowledge sources/versions/search, scoped resource resolution, permission-aware events and fresh download tickets. They do not provide verified OpenAPI schemas, staging, access policies, ticket examples, source-index contracts, deployment metadata or authorized test principals.

Phase 11 therefore mounts `DemoGalleryKnowledgeAdapter` on the existing `DemoCoreClient`. Gallery is derived from Phase 10 `DemoAgentRunAdapter` Run artifacts and review decisions. It retains artifact v1 after rejection and v2 after independent acceptance; Phase 11 alone does not ship an artifact. Phase 12 can project a separately requested, simulated delivery with a valid local receipt; see `PHASE12_REPORT_RELEASE_DECISION.md`. Draft cards are explicitly placeholders for Runs without a submission. A content hash and real deployed preview are unavailable, rather than invented. Live mode remains separate and unavailable.

The Demo Knowledge adapter advertises only text notes and decision documents. It holds synthetic versioned text in a `local-demo` browser namespace. Search hits and exact counts are calculated from authorized, project-scoped text versions; no generated prose supplies a numerical metric. Citations carry project/source/version/locator and open that exact version. Ready and stale text can be read; unavailable sources have no preview. A revoked source is excluded from lists, snippets and counts, and an existing deep link displays a redacted tombstone without title, locator, content or history. No graph or export is offered. Memory Galaxy and Obsidian are marked unavailable.

Demo preview tickets are short-lived, in-memory descriptors. Every read checks current project/source state again; an expired ticket can be renewed once. Revocation invalidates its Demo tickets and a delayed read fails after revoke. Text is rendered as a React text node inside `pre`, so embedded HTML/SVG does not execute on the app origin. These checks are local simulation, not server authorization, secure storage, malware scanning, retrieval quality or signed URL semantics. A real signed URL may remain usable until expiry; immediate revoke requires a server mechanism such as an auth proxy and must be proven by the backend.

Live exit inputs: Backend must supply reconciled Gallery/artifact/Knowledge/resolve schemas, status transitions, permission revisions, source lineage and citation identities; Storage/Security must supply preview/download ticket, expiry/revocation and isolated preview policy; DevOps/IAM must provide staging, BFF session/CSRF and authorized/revoked test identities; Product must define shipped/deployment metadata and supported source connectors; Search/Knowledge service must supply indexing, freshness and scoped count behavior. No Live integration was tested.
