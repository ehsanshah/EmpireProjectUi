# EmpireProject — بسته تکمیل مرحله‌ای UI برای Codex

نسخه 1.0 · 27 اکتبر 2026 · مبنا: قرارداد UI/Engine ضمیمه + تعامل‌های مرجع همین گفتگو

این بسته دستورهای اجرایی و برنامه تکمیل UI است؛ سورس اپ یا موتور نیست. سورس نمونه‌های فعلی در این گفتگو موجود نیست؛ Codex باید آن‌ها را در پوشه واقعی پروژه بررسی کند. هیچ نمونه‌ای از قبل قبول‌شده یا سالم فرض نشده است.

## استفاده
1. ZIP را باز کن و پوشه `empireproject-ui-delivery` را در ریشه **همان پروژه فعلی UI** کپی کن. فایل‌های سورس یا AGENTS.md فعلی را جایگزین نکن.
2. Codex را در ریشه پروژه باز کن. فایل `START_HERE_EN.md` پرامپت آغاز است؛ متن آن را کپی کن یا بنویس: «Read empireproject-ui-delivery/START_HERE_EN.md and execute Phase 00 only.»
3. فاز 00 وضعیت واقعی سورس و دستور اجرا را تحویل می‌دهد. سپس فازها با پرامپت `CONTINUE_EN.md` یکی‌یکی اجرا می‌شوند. هر فاز باید خروجی قابل بررسی، گزارش شواهد و تأیید صریح UI و UX توسط تو داشته باشد. صرف «ادامه بده» یا قبولی تست به معنی تأیید UI/UX نیست.
4. برای اصلاح همان فاز از `REVISE_EN.md` استفاده کن. برای ادامه لازم نیست همه پرامپت‌های قبلی دوباره Paste شوند.

پیشنهاد می‌شود نام پوشه ثابت بماند؛ تمام ارجاع‌های داخلی به آن وابسته‌اند. این بسته تنظیمات سراسری Codex، مدل یا API key را تغییر نمی‌دهد.

## قواعد مهم
- کار از کد موجود ادامه می‌یابد؛ نمونه‌ها دور ریخته نمی‌شوند. کد ناسازگار با قرارداد به‌صورت هدفمند اصلاح می‌شود.
- مجوز جدید کاربر برای تکمیل مرحله‌ای UI، محدودیت قدیمی «فقط یک نمونه اولیه» را در این برنامه جایگزین می‌کند. با این حال اجرای خودکار همه فازها ممنوع است؛ هر بار یک فاز اجرا و برای بازبینی توقف می‌شود.
- هویت آبی، شیشه کنترل‌شده، English/LTR پیش‌فرض و فارسی/RTL حفظ می‌شوند. رنگ سبز سند ضمیمه یک پیشنهاد موقت بوده است.
- نبود بک‌اند ساخت UI و contract fixtures را متوقف نمی‌کند. Demo و Live باید آشکار و از هم جدا باشند؛ اتصال تأییدنشده، Live موفق نامیده نمی‌شود.
- Spec 2.5 و برنامه آزمون 1.4 در قرارداد نام برده شده‌اند، اما داخل این بسته نیستند. Codex ابتدا وجود آن‌ها را در repo بررسی می‌کند؛ محتوای دیده‌نشده را نباید جعل کند.
- گزارش صوت واقعی با تست transcript تایپی فرق دارد. زمان‌بندی ساعتی تقویم با deadline فرق دارد. تأیید Agent، پذیرش انسانی و shipped یک وضعیت نیستند.
