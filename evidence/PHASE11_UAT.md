Environment: local deterministic Demo. Open [Gallery](http://127.0.0.1:5178/o/demo/p/empire/gallery?design=current) and [Knowledge](http://127.0.0.1:5178/o/demo/p/empire/knowledge?design=current). If needed, run `npm ci` and `npm run dev -- --port 5178` from the repository. The app defaults to Classic/Light with the Agent panel closed. The current 14-issue fixture and historical 12/6/2 fixture remain separate. Existing browser-local Demo records are preserved. Gallery may start empty if no Phase 10 Run exists in this browser profile; the Knowledge Demo sources are seeded. Do not clear localStorage unless you intend to discard your local Demo changes.

## UI review journey

1. Open Knowledge. Inspect the decision document, stale review note and unavailable runbook. Their identity, locator, latest version and freshness/state should be readable. Search `Original review note`; the result should show one authorized match and cite version 1. Open it and compare with version 2 in Version history. Look at [Knowledge revoked](../docs/screenshots/phase11-knowledge-revoked.png).
2. Open Gallery. If empty, follow the Phase 10 local Demo path: Intake & plan → choose **Improve checkout release readiness** → answer **Checkout web and mobile** → Create plan → acknowledge unknown budget → Approve → Request execution → Agents → simulate readiness → assign → start → submit v1 → Review request changes → start revised attempt → submit v2 → independent accept. Return to Gallery. Compare v1 `changes requested` and v2 `accepted`; both must say `not shipped`. Inspect type, project, version, reviewer, preview and lineage. Look at [Gallery accepted](../docs/screenshots/phase11-gallery-accepted.png).
3. Switch English/Persian/Arabic and Light/Dark. Persian should use bundled Vazir; Arabic should use the user-provided KFGQPC Arabic font; English should keep its original typography. Check inputs and buttons as well as text. At desktop and a narrow mobile width, inspect card density, text contrast, status labels, citation readability, long locators, RTL alignment and scrolling. Compare [Persian Dark mobile](../docs/screenshots/phase11-knowledge-mobile-fa-dark.png), [Persian Intake mobile](../docs/screenshots/persian-font-intake-mobile.png) and [Arabic Board mobile](../docs/screenshots/arabic-board-mobile.png). Stored issue and project content may remain in its source language. Check that the Agent panel remains initially closed and unrelated Work filters are absent on Gallery and Knowledge.

UI checklist for user: [ ] Gallery list/detail and empty state [ ] v1/v2 status and `not shipped` are clear [ ] reviewer and lineage are legible [ ] Knowledge ready/stale/unavailable/revoked/missing states are visually distinct [ ] citation version and locator are readable [ ] Classic/Light default [ ] Dark [ ] Vazir Persian and KFGQPC Arabic RTL with unchanged English type [ ] mobile layout [ ] no clipping or contrast defects. Automated screenshots cover selected states; the user's visual judgment remains pending.

## UX review journey

1. In Knowledge, create a local Demo decision document or note with a title, locator and text. Confirm the Demo receipt and version 1. Add a second version; open v1 again from Version history. Search a phrase found only in v1 and verify its citation opens v1, not the latest text. Use browser Back: search and selected version should restore, including the search field.
2. On the seeded stale note, click **Simulate expired ticket and recover**; the exact selected version should reappear after a new checked Demo ticket. Click **Simulate source revocation**. The title, locator, body, snippet and history should disappear; the search count should update to zero. Reload and confirm the revoked deep link remains redacted. A missing source link should instead show **Missing source**. The unavailable runbook should say preview is unavailable.
3. In Gallery, select a Run artifact version. Open its issue, plan, Run attempt and review decision. Use Back after each link; selection should return to that Gallery version. Request-changes history must remain visible after v2 acceptance. Verify the issue business status and shipping status did not change through review acceptance.
4. Use Tab and Enter for search, citations, version buttons and lineage. Switch to Arabic, then move between List, Board, Gallery and Knowledge; browser Back should restore the Board and keep RTL. Also visit Planning, Calendar, Intake, Agents and DataCart with Arabic selected. Switch project while viewing a source: results and previews should reflect only the active project. Verify the capability labels for Memory Galaxy, Obsidian, graph and export say unavailable. Preview is text only; embedded HTML/SVG is shown as text. A Demo receipt is local evidence, never a server commit or real delivery.

UX checklist for user: [ ] source create/version/search [ ] exact-version citation [ ] expired ticket recovery [ ] revoke removes restricted projections [ ] missing and unavailable recovery [ ] Gallery lineage to issue/plan/Run/review [ ] Back restores context [ ] keyboard/focus [ ] project scope [ ] honest unavailable and simulated states. Automated browser checks exercised these paths; real server access, screen-reader behavior and physical touch remain unverified.
