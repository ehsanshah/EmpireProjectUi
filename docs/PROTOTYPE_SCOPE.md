# Stage 1 — نمونه قابل اجرای EmpireProject

## هدف
کاربر فارسی‌زبان بدون یادگیری فرم‌ها و منوها با بیان قصدش، کارهای درست را در
محیط اصلی ببیند؛ کیفیت ظاهر و تعامل برای تصمیم درباره ادامه پروژه کافی باشد.
این مرحله یک برش محدود و واقعی از فرانت‌اند است؛ سرویس و AI آن شبیه‌سازی‌شده‌اند.

## خواندن مرجع
ابتدا این سند، AGENTS و ACCEPTANCE خوانده شود. در Spec کامل بخش‌های 0، 3، 6،
7.1–7.3، 10–14 و 17 را برای جزئیات مرتبط مرور کن. تنها زیرمجموعه این فایل اجرا شود.
نیازمندی‌های خارج از این مرحله در گزارش به آینده منتقل شوند، نه اینکه بی‌صدا حذف شوند.

## سطح‌های قابل ساخت
1. Today: هدف Sprint 12، سه خلاصه کم‌ارتفاع، کارهای مهم و فرمان اصلی.
2. Workspace: List، Board و Timeline خواندنی از یک Query مشترک.
3. Issue drawer: کلید، عنوان، توضیح، مسئول، وضعیت، موانع و کامنت‌های نمونه.
4. دستیار زمینه‌ای بازشونده: تاریخچه فرمان و نتیجه کوتاه، همزمان با تغییر Workspace.
5. تنظیمات کوچک و عملیاتی: فارسی/انگلیسی، روشن/تاریک، شمسی/میلادی.

منوی بزرگ با آیتم‌های بی‌اثر نساز. Portfolio، WBS، EVM، گانت کامل، داشبوردساز،
مدیریت دسترسی واقعی، Import فایل و Omnichannel در این مرحله ساخته نشوند.
Attachment button و ارسال پیام واقعی نمایش داده نشود مگر عملکرد مشخص همین مرحله دارد.
Timeline ساده برای بررسی تعامل کافی است؛ آن را موتور مسیر بحرانی معرفی نکن.

## مسیر نمایشی قطعی
داده `fixtures/sprint12.json` مرجع است: ۱۲ Issue، ۵ completed، ۱ cancelled،
۶ باز، ۲ مسدود. EMP-104 مسدود و بدون تاریخ است. شمارش‌ها را از داده حساب کن.

| فرمان | رفتار قابل مشاهده |
|---|---|
| ایشوهای مانده این اسپرینت را نشان بده | Today به List با ۶ ردیف، عنوان و Chipهای فیلتر تبدیل شود |
| فقط مسدودها | همان Query محدود شود؛ ۲ ردیف |
| بر اساس مسئول گروه‌بندی کن | همان ۲ رکورد به گروه‌های مسئول تقسیم شوند |
| تایم‌لاینش کن | همان ۲ رکورد؛ EMP-104 در بخش بدون تاریخ و دیگری روی محور |
| EMP-104 را باز کن | Drawer باز؛ زمینه و Query دست‌نخورده |
| برگرد | یک گام History برگرد؛ از Drawer ابتدا به Timeline، سپس به نمای قبل |
| همه کارهای اسپرینت را نشان بده | محدودکننده‌های قبلی برداشته؛ ۱۲ رکورد |

Cmd/Ctrl+K فرمان را باز یا Focus کند. مثال‌های انگلیسی معادل نیز پشتیبانی شوند.
فاصله، اعداد فارسی/لاتین و ی/ک عربی نرمال شوند. الگوهای محدود قابل فهم کافی‌اند؛
مدل زبانی واقعی نساز و ادعای درک آزاد همه درخواست‌ها نکن.
فرمان ناشناخته صفحه را خراب نکند؛ نمونه‌های پشتیبانی‌شده ارائه کند.
«فقط توضیح بده و صفحه را عوض نکن» با یک پاسخ توضیحی و بدون Navigation اجرا شود.

## داده و قرارداد
`MockIntentAdapter.resolve(prompt, context)` یک intent تایپ‌شده برگرداند.
`IssueRepository.query(query)` منبع واحد لیست، Count و Board/Timeline باشد.
حداقل intentها: showIssues، refineFilter، groupBy، switchView، openIssue، goBack، explain.
این نام‌ها انتخاب Stage 1 هستند و می‌توانند با نوع UIIntent سند اصلی نگاشت شوند.
UIState شامل projectId، sprintId، filter، sort، groupBy، view، selectedIssueId و revision باشد.
History یک snapshot از state است؛ chat transcript جای آن نیست.
پاسخ دیررس با requestId/revision یا cancellation نباید درخواست جدید را بازنویسی کند.
Query نباید به‌صورت کد آزاد eval شود. مدل دیتای دامنه از JSX جدا باشد.
شناسه immutable، semanticKey، tenantId، projectId و version از ابتدا حفظ شوند.
داده‌ها صرفاً ساختگی هستند. هیچ رکورد محرمانه واقعی یا کلید سرویس وجود ندارد.
آزمون ACL گسترده در Spec به مرحله بعد موکول است؛ فیلتر سمت مرورگر مرز امنیت نیست.

## ویرایش محدود
Status و Assignee در Drawer یا ردیف Inline قابل تغییر محلی باشند؛ برای تغییرات Mock
بازخورد «در نمونه ذخیره شد» و Undo فراهم شود. Reset demo داده اولیه را برگرداند.
فرمان نوشتاری گروهی مثل «این دو تا را Done کن» فعلاً پاسخ واضح خارج از دامنه بدهد؛
وضعیت‌ها را عوض نکند و ادعای موفقیت نکند. مسیر پیشرفته DoD/Transition آینده است.

## ظاهر و دسترسی
روی دسکتاپ navigation باریک، toolbar خلوت و سطح اصلی عریض؛ Assistant پیش‌فرض بسته.
شیشه ملایم فقط پوسته؛ جدول و متن خوانا. آبی Royal/Slate با Cyan محدود.
از توکن‌های بخش 13 Spec استفاده کن. ظاهر اختصاصی، نه صفحه پیش‌فرض کتابخانه.
فونت فارسی خوانا با fallback محلی؛ بارگیری شبکه نباید شرط کارکرد شود.
کلید EMP-104 و ایمیل‌ها با bdi یا dir=ltr در متن RTL حفظ شوند.
Root lang/dir تغییر کند؛ CSS logical properties؛ focus و Escape برای Drawer/Palette.
دراور موبایل fullscreen و برگرداندن Focus به کنترل آغازکننده.
در عرض ۳۹۰، ۷۶۸ و ۱۴۴۰ بررسی کن؛ جدول می‌تواند اسکرول کنترل‌شده داشته باشد.
تاریخ‌های ISO date-only را به‌عنوان روز تقویمی نگه دار، بدون جابه‌جایی timezone.
تقویم شمسی/میلادی در نمایش Timeline با date adapter؛ Datepicker و تقویم‌های دیگر آینده‌اند.

## وضعیت‌ها
Loading، empty، error/retry و command-not-supported قابل مشاهده باشند.
یک کنترل مشخص «سناریوهای نمونه» برای شبیه‌سازی empty/error و Reset مجاز است.
نمونه بدون کلید API و بدون سرویس خارجی اجرا شود. لینک‌ها و دکمه‌های موجود کار کنند.

## تحویل
سورس و دستور نصب/اجرا، build/typecheck/test، راهنمای سناریوی بازبینی و گزارش واقعی.
در پروژه جدید npm scripts برای dev، build، typecheck و test بساز؛ در پروژه موجود
package manager فعلی را حفظ کن و معادل دستورها را در گزارش بنویس.
پس از نمونه قابل اجرا و بررسی، توقف در awaiting_prototype_review.
